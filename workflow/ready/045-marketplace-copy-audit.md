# 045 — Unify and polish Candela copy across every read surface

priority: 20

## What & why

Three independent copies of the Candela pitch have already drifted apart:
`lib/emitters.js` `DESCRIPTION`, the template in `docs/marketplace-listing.md`, and
`app/index.html`'s `<meta name="description">` ("off-white paper, dark-gray ink,
desaturated pastel syntax") each say it differently. Meanwhile surfaces with hard
length limits truncate copy written for unlimited ones: the JetBrains plugin *card*
cuts mid-sentence at "...desaturated accents,".

Collapse the pitch to one module with explicit length variants, retune the voice so it
covers the dark themes too, propagate everywhere, and gate the lengths in validation so
this can't drift again.

## Spec

**Voice.** Comfort-first and mode-neutral. Drop "Light" from taglines, titles, and OG
tags — Candela ships dark companions and the brand line shouldn't exclude them. The
canonical tagline replaces `branding.ts`'s current `Light, measured for tired eyes.`
with a comfort-first, mode-neutral line in the shape of `Color, measured for tired eyes.`
(exact wording is the implementer's call within that direction). `docs/style.md`
governs prose. Keep the existing rule from `docs/marketplace-listing.md`: no theme
counts anywhere.

**One module, three lengths.** Add a zero-dependency ESM `lib/copy.js` exporting:

- `TAGLINE` — one short front-loaded line, fits the tightest surface cap.
- `DESCRIPTION` — the current ~200-char sentence, retuned to the new voice, and
  front-loaded so its truncated prefix still reads as a complete thought.
- `WHY_CANDELA` — the four-bullet block, moved from `emitters.js` unchanged in
  structure; reword only what the voice change requires.

`lib/emitters.js` imports from it instead of declaring its own constants.
`app/src/branding.ts` imports it too (`../../lib/copy.js`; Vite already has
`fs.allow: ['..']` and `app/src/themes.ts` already imports across that boundary).
Surfaces then pick the variant that fits, rather than every surface getting the long one.

**Length gates.** Extend `scripts/validate.js` (rules in `lib/rules.js` if they fit
there) with copy checks: each variant within its documented cap, no digit-based theme
counts (`/\b\d+\s+(light|dark|themes?)\b/`), and the hand-written HTML meta tags in
`app/*.html` matching the module (they're static HTML and cannot import JS, so a string
comparison is the only link). Derive the caps from the truncation points actually
observed per store and record each cap with its source next to the check.

**Propagate.** Every surface reads the new copy at the right length:

- Generated packages via `lib/emitters.js`: VS Code `package.json` + README, Open VSX
  (same `.vsix`), IntelliJ `plugin.xml` `<description>`, Zed `extension.toml` (TAGLINE,
  not DESCRIPTION), Sublime / nvim / helix / terminal-bundle install manuals.
- `app/`: `branding.ts`, `Home.tsx` hero, and the `<title>` / `description` / `og:*`
  tags in `app/index.html`, `app/themes.html`, `app/editor.html`.
- Repo docs: root `README.md` H1 + tagline, `docs/marketplace-listing.md` (becomes the
  human-readable mirror of `lib/copy.js` plus the per-store cap table — no second copy
  of the wording).
- GitHub repo metadata: description and topics, via `gh repo edit`.
- Web listing forms, done by hand at the end: JetBrains Marketplace short description +
  overview, Open VSX listing if it carries fields beyond the `.vsix`, and the Package
  Control channel entry (a PR to the upstream channel, not this repo).

Verify rather than assume for: per-theme `description` strings in
`themes/candela-themes.json` (gallery-visible blurbs), `<change-notes>` in the IntelliJ
manifest, and the release-notes template — touch each only if the voice change actually
reaches it, and note a one-line reason when it doesn't.

**Excluded.** No screenshot regeneration, no palette or token changes, no new marketplace
onboarding, no release. Publishing the retuned copy to the stores ships with the next
normal release.

## Acceptance criteria

- `lib/copy.js` is the only place the tagline, description, and "Why Candela" bullets are
  authored; `lib/emitters.js` and `app/src/branding.ts` both import it, and no second
  hand-written copy of that wording survives anywhere in the repo.
- The canonical tagline is comfort-first and mode-neutral: no repo-authored tagline,
  page `<title>`, or `og:title` claims Candela is a light-only theme set.
- `DESCRIPTION` truncated to the tightest documented store cap still reads as a complete
  thought, not a mid-clause cut.
- `node scripts/validate.js` fails when a copy variant exceeds its documented cap, when
  a theme count appears in marketing copy, or when an `app/*.html` meta description
  diverges from `lib/copy.js` — demonstrated by a temporary violation, then reverted.
- Every marketplace and install surface generated by `lib/emitters.js` renders the new
  copy at a length that fits it, verified in the generated `build/` output.
- `python3 -m json.tool themes/candela-themes.json > /dev/null`, `node
  scripts/validate.js`, `npm run build`, and `cd app && npm ci && npm run build` all pass.
- The GitHub repo description and topics match the new copy (`gh repo view`).
- The remaining web-form surfaces are applied by hand and confirmed by the user before
  this task moves to `done/`.
